# Project Context: Scoretopia

Describes the code on `main` as of 2026-11-23. For setup and operation see
`README.md`; for the architecture decision and what has been superseded in it
see `docs/adr/001-core-architecture.md`.

## Overview

Scoretopia is a Discord bot that tracks **Polytopia** game results for one
friend group. It does not take results from players. A Steam test machine runs
Polytopia, a capture playbook there writes screen captures of each game's setup
and result into a directory, and the bot reads those captures with OCR, records
the game, and posts "Game started" and "Game finished" to one Discord channel.
Players can ask for reports with a slash command.

## How a game gets recorded

1. The capture playbook writes one directory per game per kind under
   `captures.path`: `setup/<key>/` (`card.png`, `info.png`) and `result/<key>/`
   (`setup.png`, `info.png`, `victory.png`), each with a `manifest.json` written
   last.
2. `CaptureIngestService` (`domain/captures.py`) scans for directories not yet
   in the `capture_manifests` table, setups first.
3. `OcrCaptureExtractor` (`screenshot/captures.py`) reads the screens.
4. A setup capture creates the game (`GameService.start_game`) and yields a
   "Game started" post. A result capture completes the game
   (`GameService.complete_game`: winner, end points, placement, pair ratios)
   and yields a "Game finished" post. A result with no matching game creates
   the game first, with no start post.
5. A `ReportPublisher` delivers each post: Discord embeds from the bot, plain
   text from the CLI.

A capture that cannot be read records nothing and is retried on the next poll.
A game id read from `info.png` keeps a game captured twice from being posted
twice.

## Stack

- **Python 3.12+**, packaged with setuptools from `src/`.
- **Discord:** `discord.py`, gateway mode (outbound connection only), one
  guild, one `reports` channel. No privileged intents; the bot reads no
  messages.
- **Persistence:** SQLite (`data/scoretopia.db` by default). The schema is in
  `storage/schema.sql`, currently version 4, and migrates itself on open
  (`storage/db.py`).
- **OCR:** EasyOCR, with models cached under `.easyocr_models/`.
- **Config:** `config/scoretopia.yaml` (copy `config/scoretopia.example.yaml`).
  The bot token comes from the `SCORETOPIA_DISCORD_TOKEN` environment variable.
- **Tests:** `pytest`. **Lint:** `ruff`.

## Package layout (`src/scoretopia/`)

| Path | What it holds |
|------|---------------|
| `cli.py` | The `scoretopia` command: `bot`, `captures run`, `captures seed`, `report run`, `report schedule` |
| `config.py` | Loads and validates `scoretopia.yaml` |
| `domain/captures.py` | Capture manifests, capture ingest, and the "Game started" and "Game finished" DTOs |
| `domain/games.py` | `GameService`: start a game, match a game end, complete a game |
| `domain/players.py` | `PlayerService`: register, and resolve or create a player by Polytopia name |
| `domain/matching.py` | Participant-set matching, excluding bot players |
| `domain/results.py` | Result types for domain operations |
| `screenshot/` | OCR and parsers. `steam.py` handles the 1280x720 Steam frames, `game_basics.py` and `parsers.py` the screen types, `name_matching.py` OCR-tolerant name matching, `accuracy.py` the accuracy harness |
| `storage/` | SQLite connection and migration (`db.py`), row dataclasses (`models.py`), repositories (`repos.py`) |
| `reports/` | `ReportService` (active games, recent completions, win ratios), DTOs, text formatting, the cron scheduler, and the `ReportPublisher` protocol |
| `discord/` | `DiscordBotAdapter` (slash commands and the capture poll), embeds, `DiscordReportPublisher` |
| `ports/bot.py` | `BotPort`, the protocol the Discord adapter implements |
| `ingest/` | Only a logger namespace for ingest log lines |

Tables: `players`, `games`, `game_participants`, `player_pair_ratios`,
`capture_manifests`, `schema_version`.

## Entry points

- `scoretopia bot`: the long-running bot. Syncs `/register` and `/report`, then
  polls `captures.path` every `captures.poll_seconds`.
- `scoretopia captures run [--limit N]`: process the captures directory once
  and print each post, without Discord.
- `scoretopia captures seed`: mark every capture already on disk as processed,
  without reading or posting it.
- `scoretopia report run --name <report>` or `--all`: print reports.
- `scoretopia report schedule`: run the cron scheduler, printing to stdout.
- `scoretopia-extract <image>`: run OCR on one screenshot.
- `scoretopia-ocr-accuracy`: per-field accuracy across the local goldens.

## Test loop

```bash
bash scripts/lint.sh   # ruff check .
bash scripts/test.sh   # pytest
```

Both use `.venv/bin/` tools when the directory they run in has a `.venv`, and
fall back to the ones on `PATH`. They test the checkout they are run from, so
run them inside the worktree you changed.

`samples/screenshots/` is gitignored and holds local screenshots with same-stem
`.json` goldens. Tests that need those images are skipped when the directory is
empty, which is the case in a fresh worktree.

## Workflow

Issues live in this repository's GitHub Issues; see `AGENTS.md` and
`docs/agents/`. Changes are made on a branch in a worktree under `.worktrees/`
and merged through a pull request.

`SETUP.md` describes an earlier Cursor and `tdd-mcp` task-queue setup. Its
files (`.cursor/`, `tdd-mcp/`, `docs/tasks/`) are gitignored and are not part
of a checkout.

## Gotchas

- **Discord identity and Polytopia name are different things.** Neither can be
  derived from the other; `/register` links them.
- **No real names in the repository.** Do not put a player, friend, or account
  name, a user id, or a game id in code, tests, docs, issues, or pull requests.
  `tests/test_no_embedded_sample_names.py` guards the source. Captures and
  goldens are never committed.
- **OCR names are raw in capture ingest.** `name_matching.py` can resolve a
  misread name against a roster, but only the accuracy harness calls it.
- **The deploy counts log lines.** `captures run` ends with
  `Captures processed: N posted` and `Captures remaining: M` on stderr; do not
  change their text casually.
- **`docs/` is gitignored.** Files under it are tracked only when force-added
  (`git add -f`), as the ADR and `docs/agents/` are.
- **Leftovers from the removed review flow.** `ReportKind.dispute` and the
  `friend_profile` parser still exist, but nothing in ingest uses them.
